# UX leads from the code read, 2026-11-13

Found by reading every `app/ui` script against `docs/reference/ux-checklist.md` section A, before any page was driven. **They are leads, not verified bugs**: each says what the code seems to do, and a page pass (`docs/reference/ux-pass/page-pass.md`) must reproduce one on a real world before it fixes it. Grouped by file; find a page's files in `screen-map.md`. `certain` means the trace was followed to the end, `likely` and `possible` mean a step was inferred.

The ones marked **fixed** went into the first UX PR. `judgement` leads are Cain's to say yes or no to (numbered, one aspect each); never change them unasked.

Kinds: `break` (does not do what it shows), `dead-link` (nothing is wired), `silent-failure` (no word on screen), `state-lost` (a redraw drops the place or the filter), `mac-webview` (works in Chromium, not in the Mac app), `judgement`.
