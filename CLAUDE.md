# AFM: American Football Manager

A deep, realistic American football management sim modelled on Football Manager: high school prospects develop through college to the NFL, with dynamic potential and a patient season flow. Owner: Raichel (GitHub `cnbville`).

## Working rules (from Raichel)
- **Ask before every design decision.** Bring a concrete proposal, then wait for the answer. Never pick defaults yourself.
- **Default to ultra realism.** Never ask "realistic or simplified?": the answer is always the most realistic option. Ask only about deep mechanics (how things work and interact), each with a concrete proposal Raichel can agree with or adjust. Go topic by topic in order and don't skip topics.
- **Influences are noteworthy, rarely driving.** No single factor (background, family, school) should become overpowered.
- **Everything realistic and dynamic.** Reason the way real football works, and derive outcomes from attributes, not flat rules.
- **Every trial result explains why.** Each notable outcome gets a reason, so Raichel can judge it. Sanity-check results for contradictions before showing them.
- **Keep token use low and write plainly.** Use short sentences and simple structure. One checker pass per trial, no big agent fan-outs.
- **Small fixes and docs merge on green; big or new-design changes wait for Raichel's OK.** Any thread, research threads included, pushes a small fix or a docs change, opens the PR and merges it when CI is green (Cain, 2026-11-17: "why would you wait for my ok"). A big change or a new design needs Raichel's OK first. Build threads have that OK for their agreed lane: they merge to `main` and send one final reply.
- **Mark what's unconfirmed.** In docs, label Claude's proposals that Raichel hasn't answered as "proposed, not confirmed". Don't invent decisions.
- **Potential is hidden in the game.** The player-facing side never sees a true ceiling, only scouted estimates and hints. Exact potential is for trial and debug tooling only.

- `crates/afm-tools`: tooling with the `debug` feature. `stats.rs` (class summary), `bin/calibrate.rs`, and `tests/national_class.rs` (real-world calibration checks), `bin/world_trial.rs` (the section 2 trial report; `AFM_CARDS=path.json` writes full player pages, `AFM_DASH=path.json` the debug dashboard data, `AFM_RAW=dir` the full raw export as JSON lines (all three turn on the world's game log: box score totals, college stat lines and play-level situation totals, trial tooling only): every program season with engine team totals, coaches with hidden ratings, every draft pick, diversity by year, every pro career, NFL games, the NFL market's yearly counts, trades and comp picks, front offices, NFL honors and agents), `tests/world.rs`, `bin/match_check.rs`, `bin/play_trace.rs`, `bin/dynasty_check.rs` (what each position and the play callers are worth) and `bin/call_values.rs` (rebuilds the coaches' what-beats-what table, `crates/afm-engine/data/call_values.csv`), `bin/xcomp_fit.rs` (refits the expected-completion model behind CPOE at each level, `game::stats::XCOMP`), `bin/xyards_fit.rs` (refits the expected rush and YAC models behind RYOE and YACOE, `world::tally::expect`), `bin/xpass_fit.rs` (refits the expected pass model behind pass rate over expected, `world::tally::expect::XPASS`), `bin/decide_fit.rs` (refits the analysts' 4th down, try and win expectancy tables, `world::tally::decide`; rerun after engine lanes) (match engine checks), `bin/engine_hash.rs` (proves an engine speed-up plays every game the same: fingerprints per game part, then the time), `fit/` and `bin/fit_check.rs` (the scheme-fit check, lane SF0: the audit's arms on the typical team, its tables and the repeat table), `tests/match_engine.rs`, and `bin/memory_check.rs` (a world without the game log, as the game runs it: heap and resident memory after the history and each season, then each store weighed by dropping it).

## Commands
- `cargo run --release --bin afm_play`: play in a browser at http://127.0.0.1:7700 (args: port, `app/ui`, game folder; `AFM_HOME` sets the game folder). `cd app/src-tauri && cargo build` builds the desktop app (on Linux it needs webkit2gtk-4.1).
- `cargo run --release --bin afm_reader_web`: the World Reader in a browser at http://127.0.0.1:7710 (args: port, `reader/ui`, reader folder, a book; `demo <path>` writes a stand-in book).
- `cargo test --workspace --release`: all 134 tests, including a full 250,000-player class, a small 3-year world with its college and NFL games on the match engine and a living NFL, and 640 match engine games (about 25 minutes once built, almost all of it the 3-year world).
- `cargo run --release --bin world_trial -- 2026 30`: the full world with 30 years of history and the trial report. With every college game on the engine this takes about 2 minutes per season on 4 cores; `AFM_ENGINE_FROM=2026` uses the old stand-in for the history (quick checks only, about 6 minutes).
- `cargo run --release --bin calibrate -- 250000 seed`: headline stats for one class (about 2 seconds).
- `cargo run --release --bin calendar_check -- 1.0 3 2026 2100`: section 4 counters per year (commitments by month, signings, visits, portal days, declarations, stakes) and the loud events of the last year. Arguments: world scale, history years, seed, first engine year (2100 keeps every game on the stand-in, for speed).
- `cargo run --release --bin positions`: position shares (high school and draft against real data), drafted bodies against the combine, and position changes.
- `cargo run --release --bin tendency_check -- nfl 272 1 all`: the tendency proofs (spread against real, each end at 4 and 16, fit, the 10 instructions with obedience, level averages; `drift` and `centers` are debug parts). About 2.5 minutes for all parts at the NFL.
- `cargo run --release --bin ab_check -- <test|group|headline|every> [nfl|fbs|hs] [games] [seed]`: the A/B tests on attribute effects (`afm/ab-tests/plan.md`): one body number, drill, rating, habit or Dynamic Link moved for every player at a position (or one team's, the my team view), the same games on the same seeds in every arm, pure and as recruited (the generator's athletes at the same overall), matchup grids, bands from the games, checks against the NFL's real slopes and spreads (`data/real-world/ab_real.json`, from `scripts/ab_real.py`). `AFM_AB_OUT` the folder, `AFM_AB_WORLD` a world file whose NFL rosters also play the headline rows. Quick CI runs its direction test (`tests/ab_direction.rs`).
- `cargo run --release --bin fit_check -- run <fbs|nfl|hs> [games] [seed] [out] [arms]`: the scheme-fit check (lane SF0, `docs/design/scheme-fit.md`), the audit's own measure: team 0 of the league set to the level's typical team, one change an arm (a rating, a body number, a bundle, the scheme, or four men the generator draws in a body band at the same overall) on the same games as its context's typical arm, in 40 blocks (games a multiple of 40), in the audit's 12 contexts. Defaults are the audit's seeds: FBS 151 at 3,000 games an arm and the NFL 161 at 2,400 (every arm: about 2.7 hours at FBS and 2 at the NFL on 4 cores); `repeat` as the arms word plays its repeat set (run it on FBS seed 171 too, about half an hour), and `AFM_AB_WORLD` a world's NFL clubs. `fit_check read <dir>` writes the report's tables to `<dir>/report/`; `fit_check repeat fbs151=<dir> fbs171=<dir> ...` prints the repeat table across runs; `fit_check list` the arms. Every SF lane measures its items with it before and after. `fit_check values <fbs|nfl|hs|fcs> [games] [seed] [out]` (lane SF11) prices every watched rating in every system job by job for the world's fit (200,000 FBS games on seed 151, about 40 minutes on 4 cores; copy its `fit_values.csv` to `crates/afm-engine/data/`), and `fit_check world [scale] [history_years] [seed]` prints how a small world's FBS programs install and recruit by fit (stand-in games). Quick CI runs a tiny run (`tests/fit_check.rs`).
- `cargo run --release --bin fire_check -- hits <nfl|fbs|fcs|hs> [games] [seed]`, `fire_check talks <level> [seed]` and `fire_check run [games] [seed] [stakes]`: coach fire measured (`docs/design/coach-fire.md`, results in `docs/match-engine.md`, "Coach fire"): `hits` reads the test league's hardest hits (the big hit's line), big hits, sparks, footsteps, hot plays, personal fouls, targeting and ejections a team game (about 4 seconds a level); `talks` the AI coaches' pregame picks against main's; `run` prints what each prototype coach's pregame talk leaves on the same Branch-type safety and calm pocket passer (team 0 of the NFL test league), then plays them under each room against his own coach's read, A/B on the same seeds, 272 games an arm by default (about 20 seconds on 4 cores; 2,720 about 3.5 minutes; stakes 0.8 plays them as playoff games).
- `cargo run --release --bin bond_check -- [scale] [history_years] [seed]`: coach and player bonds on a small world (`docs/design/coach-bonds.md`, "World measure"): the portal, followers, trouble, mood and growth by class (the same lines run on a world before bonds), then stages by seat and class, the kinds at the top, the closest pairs, the moments, fit, need and the store's size. Defaults 0.25, 4, 261 (about 45 minutes on 4 cores).
- `cargo run --release --bin match_check -- nfl 400`: match engine averages against real 2021-25 data (`fbs`, `hs` too; add a seed and `pbp` for a play-by-play). `AFM_RUNDIAG=1` adds the run diagnostic, `AFM_AB_WORLD=<world file>` plays a world's 32 NFL clubs, or at `fbs` its FBS programs on its own schedule (`AFM_TEAMS=<file>` keeps the teams; `AFM_SEASONS=13` adds season lines, `AFM_STARTERS=1.5` the starters against the level's typical starter, `AFM_TYPICAL=ALL` moves them to him). `AFM_GAPS=1` adds the engine gaps audit's counts (`docs/design/engine-gaps.md`). `play_trace` traces one snap.
- `cargo run --release --bin play_on -- <world file> <days> <out file>`: plays a saved world on (games on the stand-in, `engine` as a 4th argument for the match engine) and prints the NFL's numbers: trades by month, rosters in week 18, unsigned veterans at cutdown, comp picks, dead money, the Hall (L12). About 4 minutes a season on the shipped world.
- `cargo run --release --bin afm_log -- build 2026 3 0.05 out 2`: a world with its log (seed, history years, scale, folder, future seasons), with time, memory and log size per season (`AFM_WORLD_LOG=off` for the same without it); `afm_log sizes <log>` and `afm_log dump <log> <kind> [year]` read a log.
- `cargo run --release -p afm-reader --bin afm_read -- build <world> [log] [book]`: the world's book (about 4 minutes and 0.7 GB for a 30-year world without its log); `afm_read <book> [page] [key=value]` prints a page (`overview`, the topic pages, `check <id>`, `odd`, `coverage`, `search <name>`, `sql <query>`).
- `cargo clippy --workspace --all-targets` and `cargo fmt --check`: CI runs both.
- CI (Cain 2026-10-29: merge on a quick check, one finishing test): every pull request and push to main runs the quick check (`ci.yml`, about 20 minutes: fmt, clippy, the build, every test that doesn't build a world, and a compile check of the desktop app). A pull request that only touches the screens (`app/ui`, `reader/ui`, `ui/showtime`) or docs skips the engine (Cain 2026-11-06): the `scope` job reads its files, then only `ui` runs (every screen script must parse, and the game's two tests that read `app/ui` when it changed). `docs/reference/how-it-works` counts as code (afm-reader's build reads it). A new test that builds a world goes in its skips. The tests that build worlds run in Full tests (`full-tests.yml`, thirteen shards on thirteen machines, about two hours; `.github/scripts/full-tests-shard.sh` lists which tests each runs, and a new screen test file or a new unit test lands in a shard on its own: add a test that builds a world of its own to a heavy shard's list there, because one world build is 13 minutes of a whole runner): nightly on main when main changed, by hand on any branch (Actions, Full tests, Run workflow) when a lane wants every test before it merges, and once on main before the world rebuild (lane 12), which waits for it to go green. The Mac app (`mac-app.yml`) builds only on main (each chip on its own machine, then joined) and by hand on a branch. Every merge gets its own build and builds run side by side (Cain 2026-11-14); a build only puts its dmg on its own release `app-<run>`, and the `publish` job (one at a time, `.github/scripts/mac-publish.sh`) moves `latest` and the downloads page to the highest finished build, never back.
- Patch notes write themselves (Cain 2026-11-15): when a Mac build publishes, `.github/workflows/patch-notes.yml` writes that version's entry in `docs/patch-notes.md` and its panel in the in-game What's new page (`app/ui/changelog.js`, between the auto markers) from every PR merged into the build (`.github/scripts/patch_notes.py`; versions that never shipped get no entry, their merges go into the next shipped one). **Every PR that changes the game carries a `## Patch note` section** (the PR template has it): `**TLDR:**` one or two positive plain sentences on what it gives the player, three to five plain bullets, `Look at:`, optionally `Title:`; or `Players: no` when nothing a player can see changed. No file names, code or PR numbers in it. Without it the notes fall back on the PR summary and What's new skips the PR. Never edit `docs/patch-notes.md` above its marker or the auto block in `changelog.js` by hand; fix the PR's section or `docs/patch-notes/curated.json` instead. How it works: `docs/game.md`, "What's new".
